# 2026-10-04 启动耗时、共用强调色与 README（0.2.4）

## 背景

用户反馈 DSH 桌面版启动偏慢，要求排查是否由自己的插件造成并优化，不得影响功能；顺带统一各插件的强调色选择，并按 awesome-dsh-plugin 的收录标准整理 README。

## 排查方法

`.qa/` 下的隔离 `dsh web` 宿主，逐个或成组加载插件，测“进程启动到打印地址”（宿主端）和“打开页面到输入框出现”（前端）。同一批配置交错跑多轮取中位数：顺序跑时机器抖动（7–13 秒）比插件差异大得多，第一次的结论因此是错的。

## 本插件的改动

- `ws`、`undici`、`qrcode` 改为用到时加载：网关在 `listen()` 里加载 `ws`；隧道只在配置了代理时加载 `undici`；二维码库在第一次生成二维码时加载，并且同一链接不重复生成。导入 `lib/index.js` 的耗时从约 230 ms 降到约 105 ms，剩下的是 `@deepseek-ai/dsh-host-webserver`（宿主本来就会加载）。
- 强调色与其他插件共用：`src/client/shared-accent.ts`（各插件内容相同）负责浏览器里的选择，`src/client/accent-sync.ts` 让它与宿主端保存的那份双向同步——电脑上改，推给宿主；手机上改，电脑下次轮询时跟上。电脑面板的黑色改为跟随宿主主题，不再只看系统深浅色。手机界面把自己的强调色写进同一个键，其他插件在手机上打开的设置页随之变色。
- README 重写：去掉发布流程和过时的“固定入口”“切换到临时公网”等说法，按功能、安装、使用、设置、安全说明、数据与隐私、工作原理、开发的顺序组织。
- `peerDependencies` 里 `@deepseek-ai/dsh-host-webserver` 的范围改为 `>=0.2.0-rc.2`，与 `dsh.engines` 一致。

## 排查结论

- 隔离宿主（`dsh web` 0.2.0-rc.2，本机）中位数：只有内置组件时宿主端约 9.1 秒、前端约 1.3 秒；加上 copylee 的六个插件，宿主端多约 1.3 秒、前端多约 0.4 秒；再加上用户安装的 11 个第三方插件，宿主端共约 14.7 秒、前端约 3.8 秒。
- 对宿主进程做 CPU 采样：13 秒里六个插件自己的代码合计约 20 毫秒，大部分时间是宿主加载自身约 3900 个模块时的文件查找与读取。六个插件带来的 1.3 秒主要是宿主对每个插件包的处理，不在插件代码里，改不了。
- 优化后对比（六轮交错）：六个插件一起，宿主端 10.58 → 10.48 秒（在误差范围内），前端 1.71 → 1.43 秒；完整组合前端 3.79 → 3.58 秒。前端的改善来自 dsh-better-display 把启动包从 8 MB 减到 1.4 MB。
