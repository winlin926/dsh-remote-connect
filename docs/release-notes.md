# 0.6.0 稳定版

本版本把公网连接从"自己配域名和转发，再输入电脑显示的 6 位密码"改成"添加一个节点"：填一个 HTTPS 地址，插件探测对面是什么、能不能连，手机和电脑各自确认一次才完成配对。同时附带了可以自己部署的公网中转服务，一台服务器接多台电脑，电脑不需要开放入站端口。

公网断开后，手机只有在确认局域网入口还是这台电脑时才会自动切过去；删除自托管节点时，电脑会顺手注销自己在服务端的注册。局域网入口可以配域名证书了，启动时会把证书、端口和节点配置检查一遍，配错直接说哪里错。

适配 DSH 0.2.2 系列，需要 Node.js 24.9 或更高版本。

## 新增

**公网节点管理**。远程连接面板里可以添加、检测、切换和删除节点。每行显示节点名称、地址、类型（隧道网关或自托管服务）、节点指纹和上次检测结果；检测失败会按原因分类（地址不对、连不上、证书有问题、对面不是 DSH 节点、身份对不上），不是只给一句"连接失败"。节点换了身份时这一行禁止连接，要点"重新确认"并重新检测之后才能继续用。

**自托管公网中转**。`remote-server/` 是一个可以直接部署的 Node 服务，用 Docker 加 Caddy 跑起来，Caddy 负责 HTTPS，注册和配对数据存在 SQLite 里。电脑主动连出到节点，不开入站端口；节点把已配对手机的请求转发回电脑，页面、接口和长连接都走这条路。一个节点可以接多台电脑，各自的凭据、设备、配对关系、缓存和隧道互不可见；注册只产生这台电脑自己的凭据，拿不到别人的东西。

**手机和电脑分别确认**。手机扫码后，配对页显示它要连的那台电脑的指纹——这个指纹由手机自己从二维码里算出来，不经过节点转发；电脑面板同时显示本机指纹。手机点确认、电脑点批准，并且两边显示的指纹一致，才签发设备授权。二维码票据 5 分钟有效、只能用一次；过期、重放、任一端拒绝都会失败。

**局域网 HTTPS**。可以给局域网入口配域名证书，手机用 `https://` 打开而不是 `http://`。启动和重载时检查证书能不能解析、域名对不对、有没有过期、私钥配不配得上；哪一项不对就在面板里说清楚，不会静默退回 HTTP。换证书后在面板点重载即可，不用重启宿主。

**公网断开后的局域网回退**。手机和电脑的连接断开 1.5 秒后，页面会向电脑要本机局域网地址，再用这个地址核对是不是同一台电脑；确认是同一台才跳转，否则提示重新扫码，不会把手机带到另一台机器上。

**插件更新**。电脑上的远程连接面板可以检查更新，并把安装交给 DSH 插件管理器；只提供兼容当前宿主的正式版，检查结果缓存 10 分钟。手机面板和远程打开的页面不显示这张卡，源码或 Git 安装则提示手动更新。

## 变更

**公网入口改成"节点"**。原来的公网连接是"域名 + 转发 + 6 位密码"，现在是一个节点地址加双端确认。升级后局域网授权继续可用；通过旧公网入口授权的手机需要重新扫码配对，因为旧授权里没有可以核对的节点身份。

**6 位连接密码和密码直连配对已删除**。密码是共享秘密，出现在截图或聊天记录里就等于开放配对页；密码直连配对还会跳过扫码和电脑确认，拿到密码就能直接入网。两条路径从存储、接口、页面到面板设置一起移除。

**删掉了没走通的 P2P 传输**。0.6 开发期间写过一整套 WebRTC/Noise 传输、TURN 中继和独立控制面，配对码也由节点签发；这些代码电脑端从没走到，发布前整段删除，共 6948 行。公网只保留一条链路：电脑主动连出的反向隧道。少一套平时没人走的传输，就少一条坏了也没人发现的失败路径；配对请求现在走同一条隧道。

**旧版网关仍可使用**。以前添加的隧道网关还能用，插件也能识别旧版节点；界面会标明是旧版，自托管节点则需要 0.6 及以上版本的插件。

## 修复

删除自托管节点时，原来只删掉本机记录，服务端注册还在，重新添加同一个地址会撞上旧注册。现在删除前先注销这台电脑在节点上的注册，连同设备、配对关系、会话和缓存一起清理；注销失败不阻断本地删除，面板会说明可能残留，并给出在服务器上清理的命令。

节点换了身份时，原来下一次检测通过就继续连接。现在会暂停这个节点的连接，面板提示身份已变化，本机确认并重新检测之后才恢复；电脑上已授权的设备不用重新配对。

节点从新版退回旧版时，不再自动跟着降级，只标记需要重新检测，避免在不知情的情况下换用一套更旧的规则。

公网断开后的局域网回退，以前只看地址能不能打开。现在必须核对指纹，宁可要求重新扫码，也不把手机导到另一台电脑。

公网"检测连通性"以前只确认对面是一个 DSH 实例，分不清"节点是谁"和"电脑是谁"。现在两件事分别校验，配对时确认的指纹也不再采信节点转发的内容。

冷启动期间，版本检查要等宿主起来才显示，用户不知道插件到底在不在；宿主掉线后手机页面看起来像卡死。现在启动阶段就显示状态，掉线时给重连横幅，断线遮罩跟随宿主的明暗主题，焦点落在重试按钮上。

多个节点之间切换时，资源缓存、设备授权和凭据不再串用；删除节点仍会立即断开该节点的在线连接和文件预览。
