# 固定公网连接实现边界

当前版本不使用免费临时公共隧道。"任意网络"通过用户自己的固定 HTTPS 域名与 frpc / 反向代理到达本机认证网关。

- 链路：手机 → 固定域名 → 用户的 frps / 反向代理 → 本机 `127.0.0.1:43128`。
- 插件不配置 DNS、日本节点或 frpc，不修改系统代理和系统服务。
- 固定域名只接受无路径、无用户信息的 HTTPS origin；Host 必须在允许列表中。
- 公网新设备先在配对页核对节点名称、类型、协议版本与主机指纹并“确认是本机”，再由电脑面板核对同一设备名与指纹批准；两次确认都完成才下发设备 cookie。
- 指纹、设备名、票据过期或已用等任一不匹配都拒绝，并把原因写到本机面板；公网模式与局域网使用同一份 `/.well-known/dsh-remote` 发现文档。
- 域名检测请求 `https://<域名>/.well-known/dsh-remote`，要求 `kind === 'gateway'`、`protocol === 1` 且 `hostId` / `fingerprint` 与本机身份一致，失败分为隧道不可达、入口不是本机（指纹不一致）、证书或域名错误三类。
- 旧版公网入口授权的设备在升级时由显式迁移函数标记 `requiresRepair`：记录可读、设备名保留，但旧 cookie 不再放行；局域网授权不受影响，迁移幂等。
- 公网连接断开时，已授权页面可向 `/rc/fallback` 询问本机局域网入口；网关先校验该入口的发现文档与本机指纹一致，boot 再核对返回的 hostId / 指纹 / origin，全部满足才跳转到局域网，否则提示重新扫码。
- ACME HTTP-01 只提供单层挑战文件。证书按 SakuraFrp 约定部署；自动续期前重新检查当前域名和公网监听状态。
- 电脑代理只用于域名检测与 ACME 请求，不影响手机流量路径。
- 首次迁移旧 `dsh-roam` 的域名与 ACME 账户状态；原目录不删除、不改写。
- 手机加载的页面由宿主提供：网关只取回宿主首页并注入 boot 脚本，公网与局域网走同一条路径，界面不因入口不同而不同。
- SSE 仍通过认证 WebSocket 载体转发（`/rc/sse`），与宿主自带事件流保持一条通道。

固定域名和证书实现参考 `dsh-roam`，电脑面板、设备配对、网关与手机界面继续以 `dsh-remote-control` 为主体。
