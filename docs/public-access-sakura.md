# 用 SakuraFrp 让手机从公网连接电脑

本教程以 Windows、`dsh-carry` 和 SakuraFrp（樱花 FRP，`natfrp.com`）为例，带你从没有域名开始，配置 HTTPS 公网入口。你也可以使用其他支持自定义域名、HTTP/HTTPS 转发并允许部署自有证书的 FRP 服务；关键是把 HTTP 80 和 HTTPS 443 都转发到这台电脑的 `127.0.0.1:43128`。

> **这是作者的个人推荐，不是广告。** SakuraFrp 是作者按下面的方式实际使用过的方案；项目与 SakuraFrp、域名注册商及 Cloudflare 均无赞助、推广或合作关系。服务规则、套餐、节点和价格由各服务商决定，可能随时调整，请以购买或开通时的官方页面为准。

## 先了解你要准备什么

- 一台持续开机并运行 DSH 的 Windows 电脑，已经安装 `dsh-carry`。
- 一个你能控制 DNS 的域名。可以在阿里云等域名注册商购买；注册商和 DNS 服务商不必是同一家。
- 一个支持自定义域名、HTTP 和 HTTPS 的 FRP 服务账号，以及对应的 Windows 客户端。
- 手机网络。首次证书申请和最终测试时，建议用手机蜂窝网络，而不是电脑所在的 Wi-Fi。

域名按年付费，首次优惠价不代表续费价；还应确认该后缀的续费价、注册限制和是否需要实名。购买前看清下一年度的续费金额。若选用中国大陆提供服务的节点或用于网站等用途，请自行向服务商确认域名备案等适用要求；不要假设所有节点、线路和用途的规则相同。

## 第一步：没有域名，先购买一个

1. 在阿里云等注册商搜索一个可注册的域名。`sanlin.xin` 只是示例，你应购买自己的域名。
2. 购买前对比首年价格和续费价格，完成注册商要求的实名或账号验证。
3. 决定 DNS 放在哪里：可以继续用注册商的云解析，也可以把域名 DNS 托管到 Cloudflare 等服务商。若使用 Cloudflare，按它提供的步骤在域名注册商处更换权威 DNS 服务器；只创建 Cloudflare 账号或添加解析记录并不会自动完成委派。
4. 本教程用 `dsh2.example.com` 代表你准备使用的子域名。把示例中的域名全部替换成你自己的，例如 `dsh2.你的域名`。通常不需要为子域名单独购买域名。

如果你暂时不想买域名，可以先在远程控制面板选择“局域网优先”，在同一 Wi-Fi 下扫码使用。离开家中或办公室网络后，局域网地址通常无法连接；要从任意网络稳定使用，请继续配置固定 HTTPS 域名或自行部署中继节点。

## 第二步：注册并创建两条隧道

1. 打开 [SakuraFrp 官网](https://natfrp.com/)，按官网要求注册账号并完成所需的实名或验证。免费资格、流量、限速、隧道数量和实名认证费用都可能变化；不要把旧教程中的额度当成永久承诺。创建前先确认账号当前可用的隧道数至少为两条。
2. 从官网“服务 / 软件下载”进入官方客户端页面，下载并安装适用于 Windows 的 SakuraFrp 启动器。首次使用时，在启动器中按页面提示绑定控制台提供的访问密钥。不要把访问密钥发给他人或放进公开仓库。
3. 在控制台创建第一条隧道：类型选择支持自定义域名的 **HTTPS（自动 HTTPS）**，节点选择一个支持建站或自定义域名的节点，目标 IP 填 `127.0.0.1`，目标端口填 **`43128`**，自定义域名填 `dsh2.你的域名`。按当前控制台的要求完成域名验证或其他设置。
4. 再创建第二条 **HTTP** 隧道，节点、目标 IP、目标端口和自定义域名使用相同设置。两条隧道的类型分别是 HTTP 和 HTTPS，不要建成两条 HTTPS。
5. 在 Windows 启动器中启动这两条隧道，并开启自动启动。等客户端显示隧道已连接后再继续。

> **端口不要填错：** `43128` 是 `dsh-carry` 的公网网关端口。不要把隧道转发到 DSH 常见的 `52728` 端口；那是 DSH 本体端口，不是这里的公网转发目标。只有在你明确修改了插件的公网端口配置时，才使用修改后的值。

启动器显示“目标连接失败”时，先检查 DSH 是否正在运行、`dsh-carry` 是否已安装并启用，以及插件面板中的远程连接是否已开启。插件未运行时，`127.0.0.1:43128` 没有服务接收连接，FRP 客户端报告连接失败是预期现象。

作者检查这套配置时，账号页面显示实名需支付 **1 元**，免费额度显示 **两条隧道、10 Mibps 限速、每月 5 GiB 流量**；客户端日志也出现过限速更新为 `10 Mibit/s` 的记录。这些是当时看到的页面和日志，不是当前报价或长期保证。你注册时若看到费用或额度不同，以自己账号的控制台为准；签到等活动流量也可能变化。

## 第三步：添加 DNS 解析

在你的 DNS 服务商控制台，为 `dsh2.你的域名` 添加一条记录：

| 记录项 | 填写内容 |
| --- | --- |
| 类型 | `CNAME` |
| 主机记录 / 名称 | `dsh2` |
| 记录值 / 目标 | SakuraFrp 控制台给这条隧道的接入域名，例如 `frp-cup.com` |
| 代理状态 | 若使用 Cloudflare，设为 **仅 DNS（灰云）** |

以隧道控制台实际提供的接入域名为准，不要照抄示例的 `frp-cup.com`。HTTP 和 HTTPS 两条隧道若共用同一自定义域名，DNS 记录通常只需添加一次，但必须满足服务商对此域名的绑定规则。DNS 更新需要时间；继续之前，确认解析结果指向服务商要求的目标。

Cloudflare 的“仅 DNS”表示它只提供 DNS 解析，不代理这条连接。不要打开橙云代理；它可能改变 HTTP-01 证书验证请求和隧道访问路径。若使用其他 DNS 服务商，按 FRP 服务商的自定义域名要求配置。

## 第四步：在插件面板设置域名并申请证书

1. 确保 DSH 正在运行，打开插件的“远程控制”面板并开启连接。
2. 在“公网入口”中的“固定公网域名”填写完整地址：`https://dsh2.你的域名`，然后点击“保存”。必须使用 `https://`，不要添加路径。
3. 开启远程连接后，点击“检测连通性”。如果检测失败，先检查两条隧道状态、CNAME 目标、域名是否已生效，以及隧道是否转发到 `127.0.0.1:43128`。
4. 检测路径确认可用后，在面板点击“申请证书”，等待面板显示证书状态。证书由插件向 Let's Encrypt 申请，通过 HTTP-01 验证；因此域名的 HTTP 请求必须能经 HTTP 隧道到达本机插件。申请时不要关闭 DSH、插件或隧道。
5. 申请成功后，面板会提示“证书已部署，请在 SakuraFrp 中重载对应隧道”。回到启动器重载 HTTPS 隧道，让它重新读取已部署的证书。HTTP 隧道不需要因为证书重载而替换。

插件默认把证书部署到 `C:\ProgramData\SakuraFrpService\FrpcWorkingDirectory`，供 SakuraFrp 客户端读取。若你改过插件的证书目录或 SakuraFrp 的工作目录，以本机实际配置为准。

## 第五步：从手机验证

1. 在插件面板再次点击“检测连通性”，确认显示可访问。
2. 在远程控制设置中选择“公网优先”，并确认连接已开启。
3. 让手机暂时关闭 Wi-Fi，使用蜂窝网络扫描面板二维码，或手动打开面板提供的公网地址。
4. 首次公网配对时，电脑面板会显示待批准设备。核对设备名称；同时在手机和电脑上核对主机指纹，确认两边一致后再批准。
5. 在手机上打开会话并发送一条无敏感内容的测试消息，确认连接可用。手机上能看到电脑的 DSH 会话，不代表应对不认识的设备批准配对。

## 续期与常见问题

- **证书续期：** 插件会管理证书申请和续期。证书更新后若面板提示需重载，在 SakuraFrp 启动器中重载 HTTPS 隧道，使 FRP 客户端加载新证书。不要仅凭“续期已开始”判断新证书已经对外生效；完成重载后再检查手机访问。
- **访问地址打不开：** 先看 Windows 启动器的 HTTP、HTTPS 隧道是否在线，再确认 DSH 和插件连接是否开启，最后核对 DNS、隧道自定义域名及 `43128` 目标端口。
- **证书申请失败：** 检查域名是否解析到正确隧道、Cloudflare 是否为仅 DNS、HTTP 隧道能否访问本机，以及插件公网入口是否已开启。DNS 刚修改时可等待解析更新后重试。
- **目标连接失败：** 如果插件尚未开启公网入口，FRP 客户端连不上本机端口是正常的。先开启插件连接，再查看隧道状态。
- **已配对手机需要撤销：** 在电脑的授权设备列表中撤销。公网连接会把手机请求转发给你的本机 DSH；只批准你信任的设备。

## 安全与费用说明

公网链接会让远程入口可从互联网访问。配对设备拥有接近本机的操作能力；请使用自己控制或信任的 FRP 服务、保护好账号密钥，并在配对时核对主机指纹。TLS 保护传输链路，但 FRP 节点会终止连接，节点运营者可能看到转发内容；这不是端到端加密。

你可能需要支付域名注册与续费费用，也可能受到 FRP 服务的实名、流量、限速、隧道数或其他套餐限制。相关价格和规则以各服务商当时页面为准，本教程不保证免费额度，也不代表任何服务商背书。
